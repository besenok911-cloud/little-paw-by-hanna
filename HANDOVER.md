# Передача проєкту власниці (Little Paw by Hanna)

Наразі все розгорнуто під акаунтами розробника (швидкий запуск). Цей документ — чек-лист чистої передачі власниці після завершення.

## Активи та кроки передачі

### 1. Домен (якщо буде свій)
- Оформити / перенести на акаунт власниці у реєстратора (domain transfer).
- DNS вказує на GitHub Pages (CNAME) — оновити при зміні.

### 2. Код і хостинг — GitHub
- Репозиторій: **Settings → Danger Zone → Transfer ownership** на акаунт власниці
  (або додати її як Owner/collaborator).
- GitHub Pages переїжджає разом із репозиторієм — окремо нічого не потрібно.
- Після трансферу URL сайту зміниться на `https://<її-акаунт>.github.io/...` —
  оновити `ALLOW_ORIGIN` у воркері та, за потреби, посилання.

### 3. Worker — Cloudflare
- Воркери **не переносяться** між акаунтами → передеплоїти під Cloudflare власниці:
  `wrangler login` (її акаунт) → `wrangler secret put ...` (всі секрети) → `wrangler deploy`.
- Новий URL воркера вписати у `scripts/main.js` → `CONFIG.bookingEndpoint`, закомітити.
- Перевірити `ALLOW_ORIGIN` у `worker/wrangler.toml` (має збігатися з доменом сайту).

### 4. Google Cloud (service account для календаря)
- Додати email власниці як **Owner** у IAM проєкту (або створити проєкт під нею).
- Календар синхронізації — вже її Google Calendar (нічого не переносити).
- За потреби перевипустити JSON-ключ і оновити секрет `SA_PRIVATE_KEY`.

### 5. Telegram-бот (сповіщення)
- Передати токен бота, або створити нового через `@BotFather` під її акаунтом.
- `TELEGRAM_CHAT_ID` має вказувати на її чат.

### 6. Instagram
- Вже її.

## Доступи, які отримує власниця
- GitHub (репозиторій), Cloudflare (акаунт з воркером), Google Cloud (проєкт),
  Telegram-бот (токен), домен/реєстратор.

## Як власниця редагує ціни без розробника
Через **веб-редактор GitHub**: відкрити `data/prices.js` на github.com → олівець →
змінити число → **Commit changes**. Сайт (Pages) пересобереться автоматично за ~1 хв.
Потрібен доступ до репозиторію (тому його і передаємо/шеримо їй).
